## 1. 项目背景

AI 记账 / 财务工作台。Fastify + TypeScript + SQLite（后端），Vue 3 + Vite + Tailwind 4（前端）。
自部署、小范围多人、Android 客户端（独立仓库）通过通知自动记账。

**核心认知（都来自生产数据实测，不是猜的）**：

| 事实 | 数字 |
|---|---|
| 交易总量 | 554 笔 / 3 用户 / 4 个月（2026-07 ~ 10）|
| 录入来源 | `app_notification` 90.7% / `manual` 7.8% / `ai` 1.4% |
| **带 `account_id` 的交易** | **1 / 554** ← 账户维度是空的 |
| 分类命中率 | 98.6%（分类没问题，**账户**才有问题）|
| 描述是渠道名的比例 | 41%（`微信支付`×98、`信用卡消费`×22）|
| 账户有期初余额的 | 2 / 13 |
| 解析耗时 | 4.0s 中位（近三周，已从 20.3s 降下来，是 provider 提速）|

**最重要的推论**：`account_id` 断 + 期初余额为 0 ⇒ **从流水回算的资产数据全是假的**。
所以资产侧的一切都必须走「手动快照」或「持仓估值」，不能用回算。

## 3. ⚠️ 尚未解决的 bug（最重要）

**用户刚补充的口径，我还没有实现，而且我现在的实现是错的。**

用户原话：

> 证券账户应该需要填写3份数值，净投入，持仓股和股数，账户余额。
> 账户总价值就是 股数*单价 + 余额 了，总价值和净投入就能算出亏损和收益

**即 `asset_snapshots.balance` 对证券账户而言是「现金余额」，不是「账户总价值」。**

我当前的错误（`server/src/lib/portfolio.ts`）：

```
netWorth = Σ(各账户最新 balance)     ← 证券账户只贡献现金，持仓市值没算进去
```

后果：证券账户有 10,000 份 ETF + ¥28,000 现金时，**持仓的 ¥86,170 从净资产里凭空消失**。

**正确的口径**：

```
账户总价值 = Σ(股数 × 单价) + 现金余额
浮盈       = 账户总价值 - 净投入
```

举例（10,000 份 @ 8.617 = 86,170，现金 28,000，净投入 100,000）：

| | 数量 | 单价 | 小计 |
|---|---|---|---|
| 黄金ETF | 10,000 | 8.617 | ¥86,170 |
| 现金 | | | ¥28,000 |
| **总价值** | | | **¥114,170** |
| 净投入 | | | ¥100,000 |
| **浮盈** | | | **+¥14,170（+14.2%）** |

### 待办清单（按优先级）

1. **改净资产口径**：`portfolio.ts` 里对「挂了持仓的账户」，贡献 = 持仓市值 + 现金；
   无持仓的账户仍用 balance。补测试。
2. **净值曲线拆两条**：持仓市值 / 现金 分开画。
   分开看才知道该不该加仓（持仓涨 + 现金降 = 在追高）。
3. **字段改名（避免同名混淆）**：`investments.total_invested` → `cost_basis`，
   且**可空**。账户级净投入留在 `asset_snapshots.total_invested`。
   单只标的的收益率在多标的时算不出来（总投入没法自动拆分），
   填了 `cost_basis` 就能量，不填只出账户级。**不要强填**。
4. **收盘后改股数 → 单价自动重算**：`costPrice = 净投入 ÷ 份额` 是**派生**的、不存储，
   所以不存在「改了股数忘了更新成本」的脏状态。这条现在**已经满足**，写个测试锁住即可。
5. **日常输入量压到最低**：每天只填**现金**；股数/净投入一个月动一次。

## 5. 约束与规矩

- **不要改 Android 客户端**（独立仓库 `/mnt/Data/billapp`）。用户明确说过。
- **迁移只用 `ADD COLUMN` / `CREATE TABLE IF NOT EXISTS`**，不重建已有表。
  上一轮实测：重建 1419 行的 `ai_parse_logs` 要 8.6ms，代价不大但收益不抵风险；
  用户明确选了 C 方案（新建独立表）。
- **不要往库里硬编码色值**（`src/lib/verify.ts` 那些是另一条线，但同一原则）。
- 中文正则**必须带数字感知边界** `(?<![\d.])…(?![\d.])`。
  已踩过三次：`0元` 是 `3.90元` 的子串（会误杀 213 条银行通知）。
  但**语义动词不要套边界**（`消费32.50` 是银行通知最常见写法，套了会降档）。
- 测试夹具用**真实抓取**的数据，不要手搓。
- 中文串里做子串匹配极其危险（没有词边界）。
