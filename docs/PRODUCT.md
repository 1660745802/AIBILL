## 1. 产品定位

### 1.1 一句话
自部署的 AI 个人财务工作台：说一句话就能记账，支持小范围多人使用。

### 1.2 设计原则
- **记账零摩擦**：说一句话就记完，不用填表单
- **记得准**：AI 解析 + 用户确认，常见输入一次通过率 > 80%
- **数据在自己手里**：自部署，业务数据不上传第三方
- **多端统一接口**：Web、App 共用同一套 API，来源可追溯
- **用户间完全独立**：各自记账互不可见。管理员默认只在管理面板做用户/系统管理；
  排障时可查看他人交易明细与 AI 解析原文，该跨用户读取**会写审计日志**（见 [API.md §12](API.md)、[DEVELOPMENT.md §5.3](DEVELOPMENT.md)）
- **AI 失败不阻塞**：任何 AI 环节出错，用户都能无感切到手动完成

### 1.3 体验指标

| 指标 | 目标 |
|------|------|
| 打开→入账步数 | ≤ 3（输入→确认→完成） |
| AI 成功耗时 | ≤ 5 秒 |
| AI 失败损失 | 0（无感切手动，输入保留） |
| 批量记账 | 3 条 ≈ 1 条的时间 |

### 1.4 记账主入口的现实

实测（2026-10，`app_logs`）：**91% 的记账来自 Android 通知自动入账**，
手动 8%、AI 1%。这直接决定了两端的分工：

- **Android 是记账入口**（通知自动记账承担 90%+ 的录入）
- **Web 是数据整合端**：看账、对账、资产、分析。所以「记一笔」在 Web 只是
  普通导航项 + `⌘K` 快捷键，不值得做成视觉主角（详见 [UI-DESIGN.md §6](UI-DESIGN.md)）

## 2. 产品口径（跨端一致）

### 2.1 统计口径

| 交易类型 | 计入支出 | 计入收入 | 计入预算 |
|---------|---------|---------|---------|
| 普通支出 | ✅ | — | ✅ |
| 普通收入 | — | ✅ | — |
| 转账 | ❌ | ❌ | ❌ |
| 退款/报销（收入分类） | — | ✅ | ❌ |

### 2.2 去重规则

| 场景 | 策略 |
|------|------|
| 幂等重试 | 同一 `client_id` → 直接返回已有记录 |
| 导入重复 | 同 user + type + amount + date + description → 提示确认 |
| App 通知重复 | 同一 `source_detail` 哈希 → 自动跳过 |

### 2.3 交易状态

| 状态 | 用途 |
|------|------|
| `confirmed` | 已确认，入账（默认值） |
| `pending` | 待确认（App 自动识别候选），**不计入统计** |

> 金额单位（分）、日期格式（北京时间）等存储约定见 [DATA.md §1](DATA.md)。

### 3.2 已废弃（deprecated）—— 本表是唯一权威

以下功能经 3 个月真实数据验证判定为无价值：**服务端表全部 0 行**，且**两个客户端都没有可达入口**。
Web 端页面与导航入口已移除；**接口与数据表暂时保留，统一标记 deprecated**，待两端对齐排期后一并移除。
本文档之外（README / API.md）只引用本表，不再各写一份。

| 功能 | 废弃的接口 | 客户端现状 | 对应表 |
|------|-----------|-----------|--------|
| 预算管理 | `/api/budgets/*` | Web 已下线；Android 有 `BudgetApi`/`Repository`/`DTO` 四层数据链路但 **presentation 层零引用**（UI 入口从未做过） | `budgets` |
| 财务目标 | `/api/goals/*` | 两端均无引用 | `financial_goals` / `goal_progress` |
| 订阅管理 | `/api/subscriptions/*` | 两端均无引用 | `subscriptions` |
| AI 记忆（接口） | `/api/memories/*` | 两端均无引用 | ⚠️ `ai_memories` **表不可删**（见下） |
| 资产快照（接口） | ~~`/api/assets/snapshot`、`/api/assets/trend`~~ | **2026-10 已删除路由**（web 零引用；Android 全 history 零引用） | ⚠️ `asset_snapshots` **表不可删**（见下） |

**为什么标 deprecated 而不直接删**：一个客户端里「数据层写全了但 UI 没入口」很容易被误读成
「功能存在只是没人用」。标 deprecated 并写明判定依据，下一个读代码的人不用重新调研。

**两条硬约束（删表 = 故障，不是清理）**：

- ⚠️ **`ai_memories` 表被 AI 解析主流程活跃读写**（解析时读记忆注入 prompt、
  修正后自动学习写入、AI 问答读取）。**只下线路由，表必须保留**。
- ⚠️ **`asset_snapshots` 表被四方活跃读写**（portfolio 曲线、dashboard/analysis 净资产、
  手填余额凭证）。删表会让这些端点集体 500。
  （这两张恰好相反：`ai_memories` 无人读表时才可删——但事实是有人读；`asset_snapshots` 有人读，不能删。）

**兼容承诺**：`GET /api/stats/dashboard` 响应结构保持不变（仍含 `budget_progress` /
`goals_top` / `subscriptions_overview`，值恒为空），以免已发布客户端解析失败。
旧 Web 路由 `/budget` `/goals` `/subscriptions` 302 到 `/me`，不 404。

## 4. 功能取舍流程（数据驱动，不靠直觉）

> 一个功能「没人用」和「不存在」是两回事——两者在代码里都可能有完整的数据链路，
> 但处置方式完全不同。用 `scripts/feature-triage.sh` 10 秒拿证据。

### 4.1 四类证据（按可信度递增，只看第一类就会出错）

| # | 证据 | 能说明什么 | 陷阱 |
|---|------|-----------|------|
| 1 | **表行数** | 服务端没数据 | 无法区分「没用」和「没做」 |
| 2 | **最近写入时间** | 是否「用了一阵就废了」 | — |
| 3 | **请求日志** | 主入口在哪 | `app_logs` **只记写操作**，没出现 ≠ 没人调；窗口 < 30 天结论不可靠 |
| 4 | **客户端可达性**（决定性） | 功能是否真的存在 | **要看 UI 层，不是数据层**：数据层四层齐备 + `presentation/` 零引用 = 事实上的死代码 |

调用量大 = 主入口，权重最大（例：91% 记账来自通知自动记账，直接改了 Web 导航层级）。

### 4.2 处置矩阵

| 服务端 | 客户端可达 | 处置 |
|--------|-----------|------|
| 有数据 | 有 | 正常使用 |
| 有数据 | 无 | 确认客户端是否要接；不接则清数据 |
| **0 行** | **有** | **不要删接口**，先问客户端：是没做好还是不需要 |
| **0 行** | **无** | **可以下线**（按 §4.3 顺序） |

### 4.3 下线安全规则（多客户端，破坏性变更）

1. **先撤前端入口，不动后端**。页面删掉、导航摘掉，接口留着。
2. **标 `deprecated` 并写判定依据**，别写「保留」——会被读成「还在用」。
3. **响应结构不动**（恒空字段保留），客户端解析不该因服务端「不写了」而炸。
4. **旧路由 302 到合理落点**，不 404。
5. **DROP 表要等客户端先删完**（跨仓库有先后顺序），且先确认真的 0 行。
6. **「接口废弃」≠「表废弃」**，分开判定（见 §3.2 两条硬约束）。

### 4.4 三个反例：`0 行` ≠ `没用`（都是真实误判）

| 表面现象 | 真相 | 教训 |
|---------|------|------|
| `user_settings` 0 行，`settings` 有 6 行 | 两张表同 migration 创建、用途不同（全局配置 vs 用户偏好），**写入路径活跃且正确**，只是没人存过偏好 | 0 行 =「还没人用」，不等于「不用了」 |
| `ai_memories` 0 行 | 被 AI 解析主流程活跃读写的表 | 「接口废弃」和「表废弃」必须分开判定 |
| `ai_memories` 0 行 + 修正率恒 0% | **反馈链路从未接通**（`parse-feedback` 零调用），管理者据此判断「AI 很准」完全相反 | 0 行 + 0 调用 + 指标恒 0 是「接线没接上」的特征，先查客户端有没有调用 |

**判定启发式**：行数 0 但接口从没被调用 → 疑似没接通，先查客户端；
接口被频繁调用但结果为空 → 功能在用；接口从未被调用且客户端无引用 → 才是真没用。

### 4.5 节奏

**每半年复盘一次**，用同一份脚本（`scripts/feature-triage.sh`，支持 `CONTAINER=` / `DB=` 参数），
让导航和功能跟着真实使用走。不要因为「感觉没人要」就动手——上一次复盘推翻了一个凭直觉做的兼容性决定。
