# 前端 UI 设计规格 · 仪表读数 (Instrument)

> 本文件是 `web/` 前端的视觉与交互契约。实现必须与本文一致；新增界面先在本文补设计，再写代码。
> 上一版「账本纸」规格见 git 历史（`fea809b`）。

---

## 0. 为什么要再改一次

上一版「账本纸」做得很干净：纸白 `#f3f5f6` + 发丝线 + 近乎零圆角 + 会计双线 + 等宽数字，
是「一本账」的忠实翻译。但它落在一个问题上——**发丝线网格 + 零圆角 + 中性灰白 + 单一克制主色**，
正是生成式界面最常见的那一档外观。它专业、克制、不难看，却不专属于
「一个人用 AI 记自己的账」这件事。

真正的区分不在皮肤，在**隐喻**。所以这一版换的不是配色，是隐喻：

> 上一版说「这是一本账」——账本是文档。
> 这一版说「**钱是读数，不是文档**」——你不是在读账本，是在看仪表。

## 1. 设计主张

### 1.1 一条硬规则：没有意义量程的数字，不给刻度带

仪表最大的风险是变成装饰。所以 `Gauge.vue` 强制调用方回答一个问题：
**这个指针指在哪，代表什么？** 量程两端必须写标签，红色区间必须有业务含义。
量程说不清楚的数字，就用一个普通数字显示，不要假装它是仪表。

推论：不是每个数字都配刻度带。仪表面上三个读数里，**只有一个**带刻度带是刻意的分布。

### 1.2 仪表面恒为深色

真实汽车仪表盘在日光下也是黑面。所以：

- **系统浅色**：浅色页面 + 深色仪表面
- **系统深色**：深色页面 + 更深一档的仪表面

个性来自「深色仪表面嵌在浅色页面里」的对比，和刻度/指针结构本身，
**不来自「把整个 App 变暗」**——后者是「暗底 + 荧光色」的通用套路，本项目不参与。

### 1.3 主操作必须是对比最强的东西

仪表上的黑色按钮在浅色系统里对比最强，在深色系统里会变成「深底压深底」退到背景里。
所以主操作单独用一组会翻转的 token：

| | 浅色系统 | 深色系统 |
|---|---|---|
| `--color-inverse` | `#171b1f`（仪表黑） | `#dfe5e9`（亮石墨） |
| `--color-inverse-fg` | `#ffffff` | `#14181c` |

**任何组件都不得硬编码色值。**

### 1.4 读数是上下文，不是装饰

仪表读数只在「这一页就是在讲我的钱」时出现：账本 / 本月 / 资产全景。
邀请码、系统日志、设置、导入、我的、回收站一律不显示。

> 教训（本次改版实测）：一开始做成「登录就常驻」，结果管理员的邀请码页面顶上
> 挂着自己的 `¥1,284,356`——那是别人的数据上下文，与该页要干的事毫无关系。
> **常驻 ≠ 到处常驻。**

## 3. 字体

自托管 IBM Plex（latin 子集，OFL），中文落系统栈。

| 角色 | 字体 | 说明 |
|------|------|------|
| 读数 / 金额 / 表格 / 邀请码 / 日志 / JSON | `IBM Plex Mono` | 灵魂字体。Plex Mono 是为机器设计的等宽体，读数用它才对味 |
| 拉丁 UI 文字 | `IBM Plex Sans` | 400/500/600 |
| 中文 | 系统栈 | PingFang SC → HarmonyOS Sans SC → Noto Sans SC |

自托管文件在 `web/public/fonts/`，6 个 woff2 共 348KB，`unicode-range` 只声明
latin 区段（中文永远不落到 Plex，避免双字体抖动）。

> **为什么不自托管中文字体**：每个字重 300–700KB，个性也不靠中文字形承载。
> 这一版的个性来自刻度结构和读数，不来自中文字重。
> `public/fonts/IBM-Plex-License.txt` 是 OFL 授权，必须随包分发。

| 层级 | 规格 |
|------|------|
| 主读数 | `1.5rem / 500 / -0.03em / tabular-nums / Plex Mono` |
| 读数标签 | `0.625rem / 600 / +0.10em / readout-3` |
| 栏头 | `0.6875rem / 600 / +0.08em` + 延伸发丝线 |
| 正文 | `0.875rem / 400 / 1.5` |
| 元信息 | `0.75rem / ink-3` |

**金额必须对齐**：全站 `tabular-nums`（`.amt` / `.readout-value` 用 Plex Mono）。
读数 ≥1 万不带小数（那两位在这个量级是噪声）；窄屏改用万/k 写法
（`¥128.4万`），**不截断**——`¥1,284…` 让人猜被吃掉的是万还是十万。

## 4. 圆角与阴影

圆角 `2 / 3 / 5 / 8px`，仪表没有圆角；圆只留给指针帽、开关、头像。

阴影只给浮层，且比上一版更收敛：
`0 2px 6px -1px rgb(0 0 0/.1), 0 18px 44px -18px rgb(0 0 0/.32)`。
仪表面用**内高光**（`inset 0 1px 0 rgb(255 255 255/.05)`）而不是投影，模拟面板。

## 5. 仪表读数（`InstrumentCluster.vue`）

三格 + 一格控制。宽屏是整块仪表面（`1.35fr 1fr 1fr auto`），窄屏压成一行吸顶读数条。

| 读数 | 视觉 | 量程 | 指针语气 |
|------|------|------|----------|
| 净资产 | 大读数 + **资产构成横条**（不是刻度带） | 占比 | 负数转 `redline` |
| 储蓄率 | 读数 + **刻度带**，目标 30% 虚线 | 0–100% | ≥30% `ok` / <0 `redline` / 其余 `amber` |
| 本月支出 | 读数 + **刻度带**，100% 刻度=与上月持平，红区 120% 起 | 0–150%（−50%~+50%） | ≥+20% `redline` / ≥+5% `amber` |
| 周期 + 新鲜度 | `‹ 2026/10 ›` + 「刚刚更新 ↻」 | — | 离开本月时出现琥珀色「回到本月」 |

**为什么净资产用横条而不是刻度带**：它的自然量程是「占比」，指针无意义。
这正是 §1.1 的应用——宁可少一个刻度带，也不要一个假的。

**点击读数 = 导航**：净资产 → `/assets`，储蓄率 → `/overview`，本月支出 → `/ledger?type=expense`。
仪表是入口，不是截图。

**新鲜度必须自报**：`/stats/dashboard` 30 秒内不重复打（数字跳动比慢更烦），
右下角显示「刚刚更新 / 3 分钟前」并可手动刷新。仪表读数如果不说明自己什么时候的，
就没有人敢信。

### 5.1 刻度带（`Gauge.vue`）

- 刻度由 `repeating-linear-gradient` 生成，不写死 DOM：每 6.25% 一根小刻度，每 25% 一根长刻度
- **刻度不随指针变色**：整条刻度是量程，指针是唯一在动的东西
  （试过「已过区间点亮」，结果整条读起来像条形码，反而看不清指针——已废弃）
- 指针 = 2px 竖条 + 顶部方帽，`left` 过渡 0.7s `cubic-bezier(.22,1,.36,1)`
- 红区 = 斜纹带 + 底边实线，一眼看出「到这里就危险了」
- 目标刻度 = 虚线到轴 + 轴上方标签

## 6. 布局与导航

### 6.1 记账是「动作」，不是「页面」

| 位置 | 形态 |
|------|------|
| 桌面侧栏顶部 | 深色按钮（`--color-inverse`）+ 快捷键提示 `N` |
| 手机右下角 | 药丸 FAB，带「记一笔」文字，回流文档**不覆盖**任何 tab |
| 任意页面 | `⌘K` / `/` 唤起快速录入（待实现，见 §7 P0） |

**FAB 为什么从居中挪到右下**：拇指自然落点在屏幕右下；居中要拇指横移，
而且它会直接压住中间那一槽的点击区（第一次改版实测就是这个 bug）。
同时给 FAB 让出了 `flex-shrink: 0` 的文档流位置，不再用 absolute 叠在上面。

### 6.2 导航槽位

| 平台 | 布局 |
|------|------|
| 桌面 ≥1024 | 232px 侧栏：品牌 / **记一笔按钮** / 每天（账本·本月）/ 偶尔（AI·资产·导入）/ 用户 |
| 手机 <1024 | 顶栏：标题 + 日期 + 头像 → 吸顶读数条（仅 cluster 页）→ 底部 **3 槽 + 右下 FAB** |

**手机 5 槽 → 3 槽**：「我的」原先占底部一格，但它是个低频聚合页；
现在从顶栏头像直达，`/me` 本来就聚合了设置/资产/导入/回收站/管理。
底部只留 `账本 / 本月 / 助手` 三个真正常用的。

### 6.3 周期是全局状态

周期控件长在仪表面上，是**唯一**的修改入口（`stores/period.ts`，落 `localStorage`）。

- 从「账本 3 月」切到「本月」不会再突然跳回当月——这是整个产品最容易记错账的地方
- 账本页不再自带 `PeriodNav`（曾经页头和仪表各显示一个月份，能不一致）
- 读数（仪表）随周期走，刷新页面后还记得在看哪个月

### 6.4 断点与间距

`sm 640 / md 768 / lg 1024 / xl 1280`，布局只用 `md` 与 `lg`。
4px 基准。内容最大宽 68rem 居中，仪表停靠区与内容区同宽同轴。

### 7.1 快捷键

只在「光标不在输入框」时生效，否则会把用户正在输入的内容吃掉。

| 键 | 行为 |
|----|------|
| `⌘K` / `Ctrl K` | 快速录入（任何页面） |
| `N` | 快速录入 |
| `/` | 有搜索框则聚焦它，否则快速录入 |
| `1` `2` `3` | 账本 / 本月 / 助手 |
| `Esc` | 关浮层 |
| `↵` | 录入框内：提交解析 |

**快速录入为何不自动关掉**：连着记第二笔（早歺 / 咖啡 / 地铁）是常见用法，
所以确认后弹层留着、输入清空、焦点回到输入框，同时 toast 与仪表读数同步更新。

### 7.2 账本的位置记忆（两个坑）

账本是无限滚动的，所以「直接 scrollTo(记住的位置)」行不通。两个必须记下的教训：

1. **存位置的时机**：不能写在 `onUnmounted`。router 会**先把新页面滚到顶部**
   （`scrollBehavior` 返回 `{ top: 0 }`）才卸载旧组件，于是那一刻读到的
   `scrollY` 已经是 0，等于永远存下 0。写在 `onBeforeRouteLeave`——
   DOM 还是旧页的时候，那才是唯一可靠的时机。

2. **恢复的算法**：目标位置超过已加载内容高度时，浏览器会把位置静默截断。
   所以记的是「目标位置」而不是一次性 scrollTo：每次分页渲染完都试一次，
   高度不够就 `loadMore()` 再等下一次回调。

   ```ts
   if (scrollHeight < target + innerHeight) {
     if (hasMore) { if (!loading) loadMore(); return }  // 还有页在路上，等它
     scrollTo(bottom); target = null; return            // 真的到底了
   }
   scrollTo(target); target = null
   ```

   注意第二个分支：把「正在加载」当成「没内容了」会只补一页就停在半路——
   症状是回到账本只跳到 855 而不是 3000。

**滚动位置的 key 必须带筛选条件**：「支出」的第 5 条不是「收入」的第 5 条，
所以 key = 月份 + 页签 + 类型 + 搜索词。

**路由的 `scrollBehavior` 对账本返回 `false`**：router 不知道第几页才够高，
只会做静默截断；组件自己有完整的恢复逻辑，router 插进来只会打架。
其余页面照常：后退/前进回原位，其它情况回顶部。
