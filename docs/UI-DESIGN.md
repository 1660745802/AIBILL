# 前端 UI 设计规格 · 仪表读数 (Instrument)

> 本文件是 `web/` 前端的视觉与交互契约。实现必须与本文一致；新增界面先在本文补设计，再写代码。
> 上一版「账本纸」规格见 git 历史（`fea809b`）。

---

## 0. 设计来源（一句话）

上一版是「账本纸」（纸白+发丝线+零圆角，见 git 历史 `fea809b`）；本版换成**仪表读数**：
「钱是读数，不是文档」——你不是在读账本，是在看仪表。区分不在皮肤，在**隐喻**。

## 1. 设计主张

### 1.1 一条硬规则：没有意义量程的数字，不给刻度带

仪表最大的风险是变成装饰。所以 `Gauge.vue` 强制调用方回答一个问题：
**这个指针指在哪，代表什么？** 量程两端必须写标签，红色区间必须有业务含义。
量程说不清楚的数字，就用一个普通数字显示，不要假装它是仪表。

推论：不是每个数字都配刻度带。仪表面上三个读数里，**只有一个**带刻度带是刻意的分布。

### 1.2 仪表面恒为深色

真实汽车仪表盘在日光下也是黑面。所以：

- **系统浅色**：浅色页面 + 深色仪表面
- **系统深色**：深色页面 + 更深一档的仪表面

个性来自「深色仪表面嵌在浅色页面里」的对比，和刻度/指针结构本身，
**不来自「把整个 App 变暗」**——后者是「暗底 + 荧光色」的通用套路，本项目不参与。

### 1.3 主操作必须是对比最强的东西

仪表上的黑色按钮在浅色系统里对比最强，在深色系统里会变成「深底压深底」退到背景里。
所以主操作单独用一组会翻转的 token：

| | 浅色系统 | 深色系统 |
|---|---|---|
| `--color-inverse` | `#171b1f`（仪表黑） | `#dfe5e9`（亮石墨） |
| `--color-inverse-fg` | `#ffffff` | `#14181c` |

**任何组件都不得硬编码色值。**

### 1.4 读数是上下文，不是装饰

仪表读数只在「这一页就是在讲我的钱」时出现：账本 / 本月 / 资产全景。
邀请码、系统日志、设置、导入、我的、回收站一律不显示。

> 教训（本次改版实测）：一开始做成「登录就常驻」，结果管理员的邀请码页面顶上
> 挂着自己的 `¥1,284,356`——那是别人的数据上下文，与该页要干的事毫无关系。
> **常驻 ≠ 到处常驻。**

## 2. 色彩（真源在 CSS）

**色值与可访问性对全部集中在 `web/src/assets/main.css` 的 `@theme`**（浅色/深色两套），本文不复制色表
——复制就是第二份真源。组件**不得硬编码色值**（复核项见 §9）。必须守住的语义约束：

- 语义分工明确：支出红 / 收入绿 / 警示琥珀 / 信息蓝；页面内颜色**只表达含义**，不做装饰。
- **仪表面恒为深色**：浅色系统下是深色面板嵌浅色页面，深色系统下整体再降一档。个性来自这个对比，
  不来自「把整个 App 变暗」。
- **主操作单独用一组会翻转的 token**（`--color-inverse`/`--color-inverse-fg`）：黑按钮在浅色下对比最强，
  深色下会「深底压深底」退到背景里，所以必须随系统翻转。
- 深色模式**跟随系统**，不做手动三档切换（自托管场景，手机端不折腾）。

## 3. 字体与金额（只锁约束，不列阶梯）

自托管 IBM Plex（latin 子集，OFL，文件在 `web/public/fonts/`）；中文落系统栈
（PingFang SC → HarmonyOS Sans SC → Noto Sans SC）。字号/字重阶梯见 `assets/main.css`。必须守住的：

- **读数与金额用 IBM Plex Mono**（机器设计的等宽体）；拉丁 UI 文字用 Plex Sans。
- **金额必须对齐**：全站 `tabular-nums`；`.amt`/`.readout-value` 用 Plex Mono。
- **读数 ≥1 万不带小数**（那两位在这个量级是噪声）；窄屏用万/k（`¥128.4万`），**不截断**——
  `¥1,284…` 让人猜被吃掉的是万还是十万。⚠️ 这条**只适用于仪表读数**，流水/表单等普通金额仍精确到分
  （由 `web/src/utils/money.ts` 的显式函数区分，不做全局切换）。

## 4. 圆角与阴影

圆角只留给指针帽/开关/头像（仪表没有圆角）；阴影只给浮层且很收敛；仪表面用**内高光**而非投影模拟面板。
具体数值见 `web/src/assets/main.css`。

## 5. 仪表读数（`InstrumentCluster.vue`）

三格 + 一格控制。宽屏是整块仪表面（`1.35fr 1fr 1fr auto`），窄屏压成一行吸顶读数条。

| 读数 | 视觉 | 量程 | 指针语气 |
|------|------|------|----------|
| 净资产 | 大读数 + **资产构成横条**（不是刻度带） | 占比 | 负数转 `redline` |
| 储蓄率 | 读数 + **刻度带**，目标 30% 虚线 | 0–100% | ≥30% `ok` / <0 `redline` / 其余 `amber` |
| 本月支出 | 读数 + **刻度带**，100% 刻度=与上月持平，红区 120% 起 | 0–150%（−50%~+50%） | ≥+20% `redline` / ≥+5% `amber` |
| 周期 + 新鲜度 | `‹ 2026/10 ›` + 「刚刚更新 ↻」 | — | 离开本月时出现琥珀色「回到本月」 |

**为什么净资产用横条而不是刻度带**：它的自然量程是「占比」，指针无意义。
这正是 §1.1 的应用——宁可少一个刻度带，也不要一个假的。

**点击读数 = 导航**：净资产 → `/assets`，储蓄率 → `/overview`，本月支出 → `/ledger?type=expense`。
仪表是入口，不是截图。

**新鲜度必须自报**：`/stats/dashboard` 30 秒内不重复打（数字跳动比慢更烦），
右下角显示「刚刚更新 / 3 分钟前」并可手动刷新。仪表读数如果不说明自己什么时候的，
就没有人敢信。

### 5.1 刻度带（`Gauge.vue`）

约束（实现细节在组件里）：刻度由 CSS 渐变生成；**刻度不随指针变色**（整条刻度是量程，指针是唯一在动的东西
——试过「已过区间点亮」，整条读起来像条形码）；红区用斜纹带 + 底边实线；目标刻度用虚线 + 轴上方标签。
⚠️ 回到 §1.1：**量程说不清的数字不要配刻度带**。

## 6. 布局与导航

### 6.1 记账是「动作」，不是「页面」

| 位置 | 形态 |
|------|------|
| 桌面侧栏顶部 | 深色按钮（`--color-inverse`）+ 快捷键提示 `N` |
| 手机右下角 | 药丸 FAB，带「记一笔」文字，回流文档**不覆盖**任何 tab |
| 任意页面 | `⌘K` / `N` 唤起快速录入（`QuickEntry.vue`），`/` 在有搜索框的页聚焦搜索框 |

**FAB 为什么从居中挪到右下**：拇指自然落点在屏幕右下；居中要拇指横移，
而且它会直接压住中间那一槽的点击区（第一次改版实测就是这个 bug）。
同时给 FAB 让出了 `flex-shrink: 0` 的文档流位置，不再用 absolute 叠在上面。

### 6.2 导航按**功能**分组，不按使用频率

单一真源：`web/src/nav.ts`。侧栏、手机底栏、「全部功能」索引页三处都从它派生。
上一版侧栏和「我的」各列一遍同一批功能，产生过重复入口——同一个功能两个入口，
人会在两者之间犹豫。

```
账目    账本 · 记一笔 · 本月结算 · AI 助手
资产    账户总览 · 投资（仅当有理财账户）
系统    导入账单 · 回收站 · 设置 · 管理面板
─────────────────
用户块               → 全部功能索引
```

三组，按**问题**分而不是按模块分：

| 组 | 回答的问题 |
|---|---|
| 账目 | 我记了什么（看流水 / 记一笔 / 看汇总 / 问 AI） |
| 资产 | 我有多少钱（汇总 / 持仓明细） |
| 系统 | 数据怎么进出、怎么配（导入 / 回收站 / 设置） |

> **曾经分过五组**（账本 / 资产 / 洞察 / 工具 / 系统），每组平均只有 2 项——
> 侧栏里组头和条目一样多，一半是标题，反而更难扫。合并后从 5 组 11 项
> 变成 3 组 10 项。

> 「记一笔」是**普通导航项**（在「账目」组里），不再单独做成顶部动作按钮：
> web 端定位是信息整合，不需要突出它。`⌘K` / `N` 快捷键保留——
> 它们不占视觉权重，只是让偶尔要手记一笔的人少点一下。

**为什么弃用「每天 / 偶尔」频率分层**：那条轴有个前提——所有页面都是同一种东西的
不同频次。加了投资之后不成立了：「账户总览」「投资组合」是**状态**，「记一笔」是**动作**，
状态和动作不在同一条频率轴上。

| 平台 | 布局 |
|------|------|
| 桌面 ≥1024 | 232px 侧栏：品牌 / 三个功能组 / 用户块 |
| 手机 <1024 | 顶栏：标题 + 日期 + 头像 → 吸顶读数条（仅 cluster 页）→ 底部 **4 槽**（账本 / 记一笔 / 账户总览 / 本月结算），无 FAB |
| `/me` | 「全部功能」索引页，按同一套三组列出；兼作退出登录入口 |

**手机底栏塞不进「组」只能放页面**。取 `nav.ts` 里标了 `mobileSlot` 的项：
账本 / 记一笔 / 账户总览 / 本月结算（4 项）。这是物理约束，不是又退回频率分层——
这四项本身也是功能性的：记录 / 动作 / 资产 / 状态。
记账在这里是普通 tab，不是凸起 FAB：**web 端定位是信息整合，不需要突出它**
（通知自动记账承担了 90%+ 的录入）。

**`/me` 保留而不是删掉**：手机上没有侧栏，它是到达「系统」组的唯一路径。
它列同样的三组，所以不是重复概念，而是与侧栏**同源**的中立索引。

### 6.2.1 管理面板的内部导航（同一原则）

管理面板按**问题**分三组，不按接口顺序平铺：
`访问`（用户与邀请码）· `自动化`（解析质量 / 自动化对照 / 通知规则 / AI 设置）· `运维`（概览 / 系统日志 / App 更新）。
概览页**异常优先**——先列「需要处理」（解析失败率、判据漂移告警、规则未激活、无分发版本），再列平铺计数；
管理面板的价值是**发现异常**，不是看总数。tab 落 URL（`/admin?tab=xxx`），可刷新/深链。
读不到数据时显示明确错误 + 重试，**不得静默空着**（那会把「读不到」谎报成「没有数据」）。

### 6.3 周期是全局状态

周期控件长在仪表面上，是**唯一**的修改入口（`stores/period.ts`，落 `localStorage`）。

- 从「账本 3 月」切到「本月」不会再突然跳回当月——这是整个产品最容易记错账的地方
- 账本页不再自带周期控件（曾经页头和仪表各显示一个月份，能不一致）
- 读数（仪表）随周期走，刷新页面后还记得在看哪个月

### 6.4 断点与间距

`sm 640 / md 768 / lg 1024 / xl 1280`，布局只用 `md` 与 `lg`。
4px 基准。内容最大宽 68rem 居中，仪表停靠区与内容区同宽同轴。

### 6.5 资产工作台：资产 = 汇总，投资 = 明细

两层，各管一件事：

| | 是什么 | 何时存在 | 放什么 |
|---|---|---|---|
| **资产**（`/assets`） | **汇总** | 永远 | 净资产、每个账户**一个数**、每日余额录入、账户设置 |
| **投资**（`/investments`） | **明细** | **仅当存在 `asset_type='investment'` 的账户** | 理财账户的持仓配置与详细盈亏 |

**为什么分两层**：你有 20 只股票时，资产页不该被 20 行持仓撑爆。资产页每账户只给一个数，
明细点进去看。这和「记一笔」降级为普通 tab 是同一条原则——**一级只放常看的整合信息**。

**导航**（`web/src/nav.ts`）：投资挂在「资产」组下，作为第二项，不算独立分组
（投资是资产的子集，不是并列概念）。

```
资产    账户总览 · 投资        ← 「投资」仅在有理财账户时出现
```

**手机**：底栏保持 4 槽（账本 · 记一笔 · 账户总览 · 本月结算），
投资**不进底栏**——它是某个账户的详情，不是一级目的地；底栏加第 5 槽会挤。
从资产页的理财账户行点进去。

### 6.6 资产页（`/assets`）

```
资产                                    2026-10-10
──────────────────────────────────────────────────
净资产  ¥13,345    +¥35 今日
──────────────────────────────────────────────────
各账户余额                    [日期 ▾]  每天记一次
──────────────────────────────────────────────────
微信          [   1300 ]      活期
支付宝        [      0 ]      活期
银行卡        [   3428 ]      活期
现金          [      0 ]      活期
证券          [  28000 ]      理财投资 ▸     ← 余额框填的是「现金」
              持仓 ¥86,170（自动算）              ↑ 点进投资页
──────────────────────────────────────────────────
              [ 记录今日 ]

账户设置（改名 / 改类型 / 额度）
──────────────────────────────────────────────────
证券   理财投资  ▸        ← 类型在行上可见；改了它，「投资」就出现在导航里
微信   活期      ▸
```

三条硬规则：

1. **理财账户的余额框填的是「现金」，不是账户总价值。**
   总价值 = 持仓市值 + 现金，其中持仓市值由系统算。若这里填总价值，
   会和持仓市值重复相加，净资产翻倍虚高。
2. **不做日期补录。** 手填是**对账修正**——覆盖当前余额并把基准线刷到此刻
   （见 `DATA.md §12`）。基准线只前进、不随所选日期倒退，否则补录会抹掉
   「那天之后已生效的」账单。接口上的 `date` 只影响快照行的日期，不参与余额计算。
3. **账户类型在行上可见**，不藏进展开层。用户看到「活期」才会想「能不能改」；
   藏起来就等于这个设置不存在（这是「找不到股票配置入口」的根因）。

### 6.7 投资页（`/investments`）

```
投资                                    2026-10-10
──────────────────────────────────────────────────
证券  [理财投资]                              总价值
                                          ¥114,170.00
  持仓市值         现金          总投入         浮动盈亏
  ¥86,170.00      ¥28,000.00    ¥100,000.00   +¥14,170.00 (+14.2%)
  ⌄ 改总投入 / 现金          ← 低频编辑默认收起
──────────────────────────────────────────────────
持仓                               盘中每 15 分钟自动更新
──────────────────────────────────────────────────
黄金ETF华安   10,000 股   现价 8.617 +1.69% 10-09   ¥86,170.00
sh518880                                          [增][减][删]
──────────────────────────────────────────────────
[ 代码 ] [ 股数 ] [ + 添加持仓 ]
代码怎么填？                                     ← 默认收起
```

**四个读数铺满整行**（桌面 4 列 / 手机 2 列），不是两两一组左对齐——
后者在宽卡片右半边会整片空着。持仓行的市值列右对齐到卡片边缘，
和头部「总价值」落在同一条竖轴上，整列数字形成一道线。

**总投入 / 现金默认收起**：这两个是低频动作（总投入只在存/取钱时改，
现金想起来才记），常驻两个输入框加一行说明会占掉一整行，而 99% 的时间
用户不看它。需要时点「改总投入 / 现金」展开，改完自动生效。

- **一个聚合页，按账户分段**（不是每个理财账户一个 tab）
- **单只持仓不记成本、不算盈亏**——只有 代码 / 名称 / 股数 / 现价 / 市值。
  盈亏只在账户级出一个数。理由见 §6.8。
- 加减仓 = 行内改股数，**不改总投入**（买卖不改变"一共投进去多少"）
- 总投入只在往账户存钱/取钱时改，是账户级的一个数

四种状态：

| 状态 | 页面表现 |
|---|---|
| 无理财账户 | 导航里不出现「投资」。直接访问 URL 时提示「去账户设置把一个账户标为理财投资」 |
| 有账户无持仓 | 空态 + **〔+ 添加持仓〕永远在**（入口由"存在理财账户"驱动，不由"存在数据行"驱动） |
| 有持仓无行情 | 现价/市值显示「—」，浮盈显示「—（待取价）」。**不显示 0** |
| 都有 | 完整读数 |

### 6.8 口径硬规则（写错就会显示假钱）

```
账户总价值 = Σ(股数 × 现价) + 现金
浮动盈亏   = 账户总价值 − 总投入
```

1. **现金不是盈利。** `浮盈 = (持仓市值 + 现金) − 总投入`。
   拿了 ¥100,000 投进去、其中 ¥28,000 还是现金，那不是亏损。
   （反例：只算 `持仓市值 − 总投入` 会把没投出去的钱算成亏。）
2. **「未配置」不是「亏损」。** 有总投入但没配持仓时，浮盈给 `null`，
   UI 说「持仓未配置」——**绝不能显示成一个负数**。
3. **「未取到价」不是 0。** 没有行情时市值给 `null`，显示「—」。
   0 会被读成"持仓归零"，是错误信息。
4. **单只不记成本。** 用户明确要求「投入不要针对单只持仓股，计算总投入就可以」。
   这同时消掉一个矛盾：页面上「头条浮盈 +14,170 / 同一只持仓行 −13,830」的正负号打架，
   根因就是单只也算了成本。废掉之后持仓行只有市值，账户级只有一个浮盈，不会再矛盾。
5. **未完整时不要塌成 0。** `netWorthComplete=false` 时应显示
   「≥¥X（N 个账户待取价）」，而不是把整个净资产显示成 ¥0。
6. **「没数据」与「全是负债」是两件事。** 构成条的空态由服务端
   `assetComposition.state` 判定：`no_readings`（「还没有记过余额」）与
   `no_positive_assets`（「没有可构成的资产（余额为 0 或全是负债）」）
   必须分开说。把欠款用户说成「还没记过余额」是谎报。
7. **负债不进构成条。** 构成条回答「钱放在哪」，只收**正资产**；
   `percent` 的分母也是正资产合计。负债另行单列（`liability`）。
   让欠款参与占比会把百分比扭曲，而且一块负色的条没法画进「正资产占比」里。
   > ⚠️ **例外**：现金为负但总价值为正的账户（透支账户挂着盈利持仓）会**同时**
   > 进构成条与 `liability` —— 构成按 `value > 0` 判、负债按 `cash < 0` 判。
   > 所以 `构成合计 − 负债合计 ≠ 净资产`，别把它当恒等式。
   连带要求：**负债块不能依附于资产行**——纯负债用户没有任何正资产行，
   欠款金额恰恰最该显示。

> 构成条本身（分组、占比、空态）是 `lib/portfolio.ts` 的口径，前端**只渲染不重算**——
> 曾经在 store 里重算，漏过 percent（组件 `toFixed` 直接抛错、整块构成不渲染）、
> 漏过空态（全负债用户被说成「还没有记过余额」）。

**读数加载不中/读不到时（三态之外的两个传输状态）**：

| 状态 | 仪表读数 | 构成副标题 | 本月页 · 资产配置卡片 |
|------|---------|-----------|-------------|
| `pending` 还在路上 | 暂用 dashboard 的同一口径读数（瞬态，防闪 0） | 中性骨架「读取中」 | 中性骨架 |
| `error` 读不到 | **「—」**，不显示另一个口径的数字 | 中性灰「资产构成读不到，稍后重试」 | 中性灰提示 |

> 「读不到」包括两种：传输报错，以及 HTTP 200 但业务码 `code != 0`。
> 两者都进 `error`；不能只在传输失败时进 —— 否则坏响应会让读数**永远停在骨架屏**，
> 既不报错也永远不恢复。

> 宁可空着也不能长期静默编一个数：`error` 时显示「—」。
> （D1 之后 portfolio 与 dashboard 是**同一个口径**，所以 pending 阶段的兜底值
> 不再是“另一个口径的更小数”；真正需要防的是**故障时用旧值/编值顶上**。）

### 7.1 快捷键

只在「光标不在输入框」时生效，否则会把用户正在输入的内容吃掉。

| 键 | 行为 |
|----|------|
| `⌘K` / `Ctrl K` | 快速录入（任何页面） |
| `N` | 快速录入 |
| `/` | 有搜索框则聚焦它，否则快速录入 |
| `1` `2` `3` | 账本 / 本月 / 助手 |
| `Esc` | 关浮层 |
| `↵` | 录入框内：提交解析 |

**快速录入为何不自动关掉**：连着记第二笔（早歺 / 咖啡 / 地铁）是常见用法，
所以确认后弹层留着、输入清空、焦点回到输入框，同时 toast 与仪表读数同步更新。

### 7.2 账本的位置记忆（两个坑）

账本是无限滚动的，所以「直接 scrollTo(记住的位置)」行不通。两个必须记下的教训：

1. **存位置的时机**：不能写在 `onUnmounted`。router 会**先把新页面滚到顶部**
   （`scrollBehavior` 返回 `{ top: 0 }`）才卸载旧组件，于是那一刻读到的
   `scrollY` 已经是 0，等于永远存下 0。写在 `onBeforeRouteLeave`——
   DOM 还是旧页的时候，那才是唯一可靠的时机。

2. **恢复的算法**：目标位置超过已加载内容高度时，浏览器会把位置静默截断。
   所以记的是「目标位置」而不是一次性 scrollTo：每次分页渲染完都试一次，
   高度不够就 `loadMore()` 再等下一次回调。

   ```ts
   if (scrollHeight < target + innerHeight) {
     if (hasMore) { if (!loading) loadMore(); return }  // 还有页在路上，等它
     scrollTo(bottom); target = null; return            // 真的到底了
   }
   scrollTo(target); target = null
   ```

   注意第二个分支：把「正在加载」当成「没内容了」会只补一页就停在半路——
   症状是回到账本只跳到 855 而不是 3000。

**滚动位置的 key 必须带筛选条件**：「支出」的第 5 条不是「收入」的第 5 条，
所以 key = 月份 + 页签 + 类型 + 搜索词。

**路由的 `scrollBehavior` 对账本返回 `false`**：router 不知道第几页才够高，
只会做静默截断；组件自己有完整的恢复逻辑，router 插进来只会打架。
其余页面照常：后退/前进回原位，其它情况回顶部。
